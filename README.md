# SAE Evening Project — интерпретация GPT-2-small через Sparse Autoencoder

**Идея:** Residual stream GPT-2 хранит гораздо больше
концепций, чем у него измерений (гипотеза суперпозиции) — из-за этого
отдельные нейроны редко имеют понятный смысл. Sparse Autoencoder (SAE)
учится раскладывать этот плотный вектор в широкий, но почти весь нулевой
набор фич — и если реконструкция при этом остаётся точной, найденные фичи
с большой вероятностью соответствуют отдельным, вычленимым концепциям.

## Стек

- **Модель:** GPT-2-small, через `transformer_lens.model_bridge.TransformerBridge`
- **SAE:** простой ReLU-автоэнкодер, написан с нуля на PyTorch (без SAELens)
- **Датасет:** [`Salesforce/wikitext`](https://huggingface.co/datasets/Salesforce/wikitext) (`wikitext-103-raw-v1`), стриминг
- **Железо:** RTX 4070

## Структура репозитория

| Файл | Назначение |
|---|---|
| `collect_activations.py` | Блок 1 — сбор активаций residual stream, запись на диск чанками |
| `sae_model.py` | Архитектура SAE (encoder/decoder) |
| `sae_dataset.py` | Shuffle-буфер: читает чанки с диска, отдаёт перемешанные батчи |
| `train_sae.py` | Блок 2 — цикл обучения SAE, логирование L0 / dead features |
| `interpret_features.py` | Блок 3 — поиск top-примеров текста для выбранных фич |
| `feature_report.md` | Результат работы `interpret_features.py` (генерируется) |
| `activations/`, `checkpoints/` | Артефакты прогонов (в `.gitignore`, тяжёлые) |

## Как воспроизвести

### 0. Установка

```bash
pip install -r requirements.txt
```

### 1. Соберём активации

```bash
python collect_activations.py --n_tokens 2000000 --layer 6 --out_dir ./activations
```

Прогоняем ~2М токенов текста через GPT-2-small, снимаем residual stream
после 6-го из 12 блоков (`hook_resid_post`) и сохраняем на диск чанками
по 100k токенов. Позиции BOS/padding (`<|endoftext|>`) исключаются из
сбора — см. раздел "Уроки" ниже.

### 2. Обучим SAE

```bash
python train_sae.py --activations_dir ./activations --dict_size 2048 --l1_coeff 3e-3 --n_steps 3000
```

Простой ReLU SAE (`d_model=768 → dict_size=2048 → d_model=768`) с
loss = MSE(реконструкция) + λ·L1(код). На каждом чекпоинте в консоль
логируются L0 (среднее число активных фич на токен), доля мёртвых фич и
быстрая прокси-метрика `variance_explained` (не путать с честным loss
recovered — см. "Известные ограничения").

### 3. Проинтерпретируем фичи

```bash
python interpret_features.py --checkpoint ./checkpoints/sae_dict2048_l1_0.003.pt
```

Берём свежий (не участвовавший в обучении) кусок текста, прогоняем через
модель + обученный SAE, для нескольких фич (частые + случайные) находим
top-8 токенов с наибольшей активацией и контекст вокруг них. Результат —
`feature_report.md`, который нужно прочитать глазами и вписать гипотезы.

## Метод: как искать и подтверждать фичи

1. Найти top-N примеров текста, на которых фича активируется сильнее всего.
2. Прочитать глазами, сформулировать гипотезу ("активируется на именах
   после Mr./Mrs.", "реагирует на числа в финансовом контексте" и т.п.).
3. *(Не сделано в этой вечерней версии, естественное продолжение)*
   Проверить гипотезу не только по корреляции, а причинно: заablировать
   фичу и посмотреть, меняется ли поведение модели на предсказуемый лад.

- L0 и доля мёртвых фич: из последних строк лога `train_sae.py`
- Интерпретированные фичи и гипотезы: см. `feature_report.md`
